# LVIS calibration — committed results

Outputs of the calibration pipeline, committed so the README's claims are
checkable without re-running a multi-hour job. Everything here is small
(~1.1 MB total); the inputs that produced it (100,169 image embeddings,
1 GB of LVIS annotations) stay out of git and are regenerated by `00_`–`02_`.

**All values below were produced at `config.FBETA = 0.5`** (~80/20
precision/recall lean). Numbers from the earlier `β = 0.816` run are not
represented here — see the "Fβ weighting history" section of the parent README.

## Files

| File | Produced by | What it is |
|---|---|---|
| `thresholds.npy` | `03_calibrate_thresholds.py` | `(1203,)` float32 — naive full-split per-tag cosine thresholds. Range 0.200–0.470, mean 0.409. |
| `balanced_thresholds.npy` | `07_balanced_calibration.py` | `(1203,)` float32 — **the authoritative set.** Calibrated on balanced pos/neg subsets. Range 0.200–0.400, mean 0.335. |
| `bucket_thresholds.json` | `03_calibrate_thresholds.py` | Bucket-level fallback thresholds for tags too rare to calibrate individually: weak 0.45 (337 tags), medium 0.43 (461), high 0.41. |
| `calibration_table.json` | `03_calibrate_thresholds.py` | Full per-tag record: chosen threshold, bucket, confidence flag, and the metrics at that point. |
| `per_tag_metrics.csv` | `06_per_tag_metrics.py` | 1203 rows — confusion matrix + metrics under the **naive** regime. |
| `balanced_per_tag_metrics.csv` | `07_balanced_calibration.py` | 1203 rows — the same under the **balanced** regime. |
| `ablation.json` | `05_ablation.py` | Per-text-source vs combined macro Fβ. |
| `tag_order.json` | `01_build_text_classifiers.py` | Row order for both `.npy` files. **Required to interpret them** — index *i* of `thresholds.npy` is the tag at index *i* here. |

## Headline numbers

Recomputed from the committed CSVs, not copied from prose:

| Regime | mean precision | mean recall | mean weighted-F1 |
|---|---|---|---|
| balanced (`07_`) | **0.825** | 0.767 | **0.800** |
| naive (`06_`) | 0.116 | 0.127 | — |

The naive numbers are *not* a bug. With positives-only ground truth, a rare tag
has ~1–50 positives against ~100K implicit negatives, so precision is
structurally floored regardless of β. `zebra` reaching precision 0.96 in the
same run confirms false-positive counting is correct. Read naive numbers only
set-vs-set, never in isolation.

## Which thresholds to use

Use `balanced_thresholds.npy`. The naive set is crushed by the negative base
rate and calibrates too high to be useful in deployment.

Two caveats that matter:

1. **Rare-tag rows are noise.** 222 tags have ≤10 images in their balanced
   subset. Trust a row in proportion to its `subset_total` column (median 74).
2. **Balanced metrics are optimistic.** They measure intrinsic separability, not
   deployment performance. Real base rates are far more hostile, so production
   precision will be lower than this CSV shows.

## Reproducing

```bash
python 03_calibrate_thresholds.py
python 06_per_tag_metrics.py
python 07_balanced_calibration.py
```

Requires `data/image_embeds/` and `data/text/` to exist — see the parent README
for the full run order from `00_download_lvis.py`.
