# Environment for the RAM++ vs TinyCLIP comparison app.
#
# This app is the only place in the repo where RAM++ (torch) and TinyCLIP
# (onnxruntime) must run in ONE process, which forces a dedicated venv.
#
# Install:  ./setup_venv.sh        (Linux / jovyan)
#           ./setup_venv.ps1       (Windows)
#
# ─────────────────────────────────────────────────────────────────────────────
# BOUNDS POLICY
#
# Versions are left open so wheels resolve against whatever Python the host
# image ships. The FOUR upper bounds below are NOT stylistic — each marks a
# real, reproduced incompatibility that breaks the app at import or at model
# load. Do not relax them without re-running verify_env.py --full.
# ─────────────────────────────────────────────────────────────────────────────

# --- RAM++ (torch side) ---
# CPU wheels are fine; setup_venv.sh installs these from the pytorch CPU index
# unless you pass --gpu.
torch>=2.0
torchvision>=0.15

# HARD UPPER BOUND — and NOT at the 5.0 boundary. RAM's vendored BLIP-era
# ram/models/bert.py does:
#   from transformers.modeling_utils import (
#       PreTrainedModel, apply_chunking_to_forward,
#       find_pruneable_heads_and_indices, prune_linear_layer,
#   )
# modeling_utils.py stopped re-exporting apply_chunking_to_forward from
# .pytorch_utils between 4.55.0 (present) and 4.56.0 (gone) — the function
# itself still exists in pytorch_utils.py, just not re-exported where RAM
# imports it from. Nowhere near the 5.0 boundary the first cut of this bound
# assumed.
#
# Bisected against upstream source on 2026-08-06 (present: 4.44.2, 4.49.0,
# 4.52.0-4.55.0; absent: 4.56.0, 4.56.2, 4.57.6). Reproduced live: pip resolved
# 4.57.6 under an earlier `<5` bound, then 4.56.2 under an earlier `<4.57`
# bound, and both failed identically at RAM model construction.
transformers>=4.40,<4.56

# transformers <4.56 caps huggingface-hub at <1.0 anyway. Stated explicitly so
# pip resolves in one pass instead of backtracking through dozens of candidates.
huggingface_hub<1.0

# RAM upstream pins timm==0.4.12, which predates Python 3.11. 0.9+ still ships
# the timm.models.layers shim that ram/models/swin_transformer.py imports.
timm>=0.9,<2

# HARD UPPER BOUND. RAM's Swin position-bias interpolation calls
# scipy.interpolate.interp2d, REMOVED in SciPy 1.14.
# Symptom: AttributeError while loading the checkpoint.
scipy<1.14

pandas>=2.0
fairscale>=0.4.13

# --- TinyCLIP (onnxruntime side) ---
# onnxruntime-extensions supplies the CLIPTokenizer custom op. 0.12 is the
# oldest release that builds the tokenizer graph this repo's asset was made
# with; newer is fine.
onnxruntime>=1.17
onnxruntime-extensions>=0.12

# --- shared ---
# HARD UPPER BOUND. gradio 6 requires huggingface-hub>=1.2, while
# transformers <5 requires <1.0. The two cannot coexist; pip will either
# backtrack forever or silently break transformers.
gradio>=5,<6

# HARD UPPER BOUND. onnxruntime has no numpy 3.x wheels yet.
numpy>=1.26,<3

pillow>=10
tqdm>=4.60
