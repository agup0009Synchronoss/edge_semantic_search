# Research

Three evaluation workstreams behind the Android app, plus the shared code they
all build on. Read them in dependency order — each consumes the previous one's
output.

```
common/                       tinyclip_encoder.py + assets/*.onnx + templates.py
   │                          the Android-exact encoder, ONE copy
   │
   ├──► vitb32_benchmark/     TinyCLIP vs full CLIP ViT-B/32, 108K Visual Genome images
   │                          "how much quality does the 8M model give up?"
   │
   ├──► lvis_calibration/     per-tag cosine thresholds on LVIS-v1, 1203 tags
   │       │                  "what cosine means the tag is present?"
   │       │
   │       └── results/balanced_thresholds.npy
   │                    │
   └────────────────────┴──► ram_comparison/   TinyCLIP vs production RAM++, 4585 tags
                                               "how does it compare to what ships today?"
```

## `common/` — the shared floor

| File | What |
|---|---|
| `tinyclip_encoder.py` | Android-exact TinyCLIP. Replicates `ImagePreprocess.kt` and `Tokenizer.kt` byte-for-byte, **including the deliberate double BOS/EOT wrap**. Change that and embeddings stop matching the calibration that produced every committed threshold. |
| `assets/*.onnx` | The encoders. Byte-identical to `app/src/main/assets/`. |
| `templates.py` | 85 prompt + 3 question templates, and `normalize_label()`. |
| `ssl_bypass.py` | Corporate-TLS workaround. **Must be imported before transformers/gradio** — they open connections at import time. |
| `paths.py` | `REPO_ROOT`, shared-module resolution, and `$VG_DATA_ROOT` for the external Visual Genome corpus. |
| `verify_assets.py` | Checks every committed ONNX against `ASSETS.sha256`, and that all copies agree. |
| `parity_assets.py` | Numerical parity between two asset directories. Hashes say files differ; this says whether that *matters*. |

Every workstream has a `config.py` that puts `common/` on `sys.path`. Import
`config` first, always — it is what makes the shared modules importable.

## Results at a glance

| Question | Answer | Detail |
|---|---|---|
| Do the ONNX encoders in the two locations match? | Yes. Text bit-identical; vision within 4.2e-07 (~3 float32 ulp) | `common/parity_assets.py` |
| Can per-tag thresholds be calibrated for LVIS? | Yes, in the balanced regime: mean precision **0.825**, recall **0.767**, weighted-F1 **0.800** | [`lvis_calibration/results/`](lvis_calibration/results/) |
| ...and in the naive full-split regime? | Mean precision **0.116** — floored by base rate, not a bug | same |
| Do LLM descriptions beat prompt templates? | Marginally: **+1.8% macro Fβ**, from **4.4x fewer strings** (20 vs 88) | [`ram_comparison/results/`](ram_comparison/results/) |
| How much of RAM++'s vocabulary can TinyCLIP calibrate? | **1037 / 4585** (22.6%). The rest ride a global knob | same |

Two honesty notes that matter more than the headline numbers:

1. **The naive and balanced regimes are not comparable.** Balanced metrics
   measure intrinsic separability on a 50/50 subset; naive metrics sit on the
   real base-rate floor. Balanced numbers are optimistic for deployment. Never
   quote one as if it were the other.
2. **Rare tags are noise.** 222 of the 1203 LVIS tags have ≤10 images. Their
   thresholds inflate the `weak`-bucket mean. Trust any row in proportion to
   its `subset_total` column (median 74).

## Environments

The three workstreams need **two separate virtualenvs**, and that is not
incidental:

| venv | Used by | Why it must be separate |
|---|---|---|
| `vitb32_benchmark/venv_clip` | vitb32_benchmark, lvis_calibration | Runs current transformers |
| `ram_comparison/venv_ramclip` | ram_comparison | RAM's vendored BLIP-era `bert.py` imports `apply_chunking_to_forward`, removed in transformers 5.x |

Two further pins in `venv_ramclip` were found the hard way:

- **gradio 5.x, not 6.x** — gradio 6 needs `huggingface-hub>=1.2`; transformers 4.44 needs `<1.0`. Unresolvable together.
- **scipy 1.13.1** — RAM's Swin position-bias interpolation calls `scipy.interpolate.interp2d`, removed in SciPy 1.14.

Setup and full run instructions: [`../docs/reproducibility.md`](../docs/reproducibility.md).

## What is and is not committed

Committed: all source, the ONNX encoders, the LLM-generated descriptions
(not regenerable), and small `results/` artifacts (~1.5 MB).

Not committed, regenerated by the `00_*` scripts: LVIS annotations (~1 GB),
COCO train2017 images, `img_matrix.npy` (205 MB), the RAM++ checkpoint (2.8 GB),
the classifier `.npy`/`.jsonl` files, and `vg_tinyclip_embeddings.pkl` (226 MB).

Also excluded: `ram_comparison/mldev_asset/`, which holds internal Verizon
production tag frequencies and S3/Spark pipeline code. It is kept on disk as a
reference for what production RAM++ tagging looks like, and must not be
committed to this remote.
